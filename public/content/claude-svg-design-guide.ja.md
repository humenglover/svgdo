# Claude AI + SVG: もうあの地獄のようなパスを手書きするのはやめた

## ぶっちゃけ、SVGのパスを手書きするのは人間のやることじゃない

正直なところ、フロントエンドのベテラン諸君。酒を飲みすぎた後や、深夜のデスマーチ中に、`<path d="M10 10 C 20 20, 40 20, 50 10" />` みたいなコードを見つめながら、自分の人生の選択を問い直したことはないだろうか？

私がこの業界に入ったばかりの頃を思い出す。波線のカード背景を描こうとして、3時間もモニターの前に座り、ベジェ曲線の座標を手動で調整していた。そして最終的に出来上がったのは、まるで潰れたタイヤのような何かだった。
あの時の気持ちをどう表現すればいいだろうか？たぶん、こんな感じだ：

![When you try to code SVG paths by hand](/content/images/svg-ai-guide/meme-coding-pain.gif)

わかるだろう。あの頃、我々は「習うより慣れろ」と信じていた。「十分に努力すれば、脳内でキャンバスを自動的にイメージできるようになる」と本気で思っていた。だが現実は？デザイナーが派手なベクター画像を渡してくるたびに、私は `<img src="xxx.png">` で乱暴に解決していた。スケーラビリティ？パフォーマンス最適化？知るか。この老いぼれはもうタイプするのも疲れたんだ。

その後、Figmaが登場して我々を救ってくれた。手書きする必要はなくなり、エクスポートして終わりだ。
しかし、また別の問題が発生した。ちょっとしたグラフィックのために、重いデザインソフトを立ち上げたくないことが多い。あるいは、さらに悪いことに、**コードだけで生成され、設定可能で、動的なデータ可視化チャート**が必要になることがある。これは本当に頭が痛い。

Claude AIが「コード生成の超能力」を持って天から舞い降りてくるまで、私は気づかなかった。ああ、もう自分で絵を描く必要なんてないんだ、と。

## Claude AI がベクターの魔法と出会う時

君たちは、自然言語を使って機械に絵を描かせたことがあるだろうか？Midjourneyが編集不可能な派手なビットマップを生成するような話じゃない。HTMLに直接インライン化できて、容量もたった数キロバイトの、堅牢で標準化された `<svg>` コードの話だ。

初めて試した時、私はプロンプトボックスにたった一文だけ入力した：「SVGを使って、ミニマリストな円グラフを描いて。テック系のデザインにして、3色使って、グラデーションもつけて」

3秒。
3秒後、画面にはほぼ完璧なSVGコードが吐き出された。私の反応は文字通りこれだった：

![Mind blown by AI SVG generation](/content/images/svg-ai-guide/meme-mind-blown.gif)

まるで、自分がまだ基本のパンチを練習しているのに、誰かにライトセーバーを手渡されたような気分だった。Claudeのおかげで、我々は今、自信を持ってこう言える。「俺は口でコードを書くんだ」と。

さて、次に、「手を動かす代わりに口を動かす」という究極の奥義を伝授しよう。無駄話はなしだ。実践あるのみ。

## 第一の型：我々の最強の武器を起動する

Claudeにコードを書くよう命令する前に、吐き出されたコードをテストして微調整する場所が必要だ。
ローカルの `.svg` ファイルとして保存して、それをブラウザにドラッグするなんて言わないでくれ。それは石器時代のやり方だ。

我々のプラットフォームの編集インターフェースを見てほしい（ここが君の新しいホームだ）：

![Real Platform Usage 1](/content/images/svg-ai-guide/platform-usage-1.png)

Claudeが生成したコードを左側（または該当するコードボックス）に放り込むだけで、右側に即座にプレビューが表示される。色が変？位置が少しずれてる？プラットフォーム上で直接修正すればいい。ここでスムーズにコードをフォーマットしたり、フィルターを追加したりすることさえできる。だからこそ、このチュートリアルを読みながら、我々のエディタを開いておくことを強くお勧めする。

## 第二の型：汎用プロンプトテンプレート（核心部）

ただ「絵を描いて」と叫ぶだけではダメだ。Claudeも本質的にはプログラマーなのだから、正確な要件を伝える必要がある。私は、SVGを生成するための汎用的なプロンプトテンプレートをまとめた：

> **「あなたはシニアフロントエンドエンジニアであり、UIデザイナーです。純粋なSVGを使用して [必要なものを記述] を描画してください。**
> 
> **具体的な要件：**
> **1. 寸法：[例: viewBox="0 0 800 600"]**
> **2. スタイル：[例: ミニマリスト、フラット、グラスモーフィズム、サイバーパンク]**
> **3. 配色：[色を指定、例: 背景に #1e293b を使用し、メインカラーは #3b82f6]**
> **4. 詳細：[影、角丸、特定のテキストなど、含めるべき特定の要素]**
> 
> **正しくフォーマットされ、直接レンダリング可能なSVGコードのみを出力してください。余計な説明は不要です。」**

### ライブデモ：モダンなデータダッシュボードを描く

このテンプレートを適用して、データダッシュボードのプレースホルダーを描くよう頼んでみよう：

```text
あなたはシニアフロントエンドエンジニアであり、UIデザイナーです。純粋なSVGを使用して、モダンなデータダッシュボードのプレースホルダーを描画してください。

具体的な要件：
1. 寸法：viewBox="0 0 1000 600"
2. スタイル：グラスモーフィズム、背景は暗いグラデーション。
3. 配色：深い青の背景、半透明の白のパネルカード、蛍光グリーンと蛍光パープルのデータハイライト。
4. 詳細：曲線の折れ線グラフ、半円ドーナツグラフ、およびいくつかのダミーテキストのプレースホルダーを含める。

正しくフォーマットされたSVGコードのみを出力してください。余計な説明は不要です。
```

そのコードを受け取り、我々のエディタに貼り付けてみれば、結果が驚くほど良いことがわかるだろう。これがAIの力だ。

![Typing prompts like a hacker](/content/images/svg-ai-guide/meme-hacker-typing.gif)

見てみろ。以前よりずっと速くコードが書けているだろう？要件を打ち込んで、あとはコードをコピペするのを待つだけだ。

## 第三の型：プラットフォームでの「仕上げ」

Claudeは強力だが、盲目だ（LLMは自分の出力結果を実際に*見る*ことはできない）。時々、レイヤーを間違って重ねたり、テキストが境界を少しはみ出したりする。

ここでこそ、我々のプラットフォームが真価を発揮する！
エディタで二次調整を行っている状態を見てほしい：

![Real Platform Usage 2](/content/images/svg-ai-guide/platform-usage-2.png)

プラットフォーム上では、直感的に以下のことができる：
1. **座標の微調整**：ずれた `cx` や `cy` パラメータを修正する。
2. **色の入れ替え**：AIが選んだ色がダサいと思ったら、エディタ上で直接ブランドカラーに変更する。
3. **インタラクティブ性の追加**：SVGを動かしたい？コードに直接 `<animate>` タグを追加するか、エクスポートして外部のCSSとJSを使えばいい。

我々のエディタはリアルタイムレンダリングをサポートしている。つまり、Claudeと「ペアプログラミング」ができるということだ。Claudeが大きな構造を担当し、君がエディタで細部を調整する。1+1 > 2 になる組み合わせだ。

## サバイバルガイド：AIの「複雑な幾何学」を信用するな

ここまで素晴らしいと褒めちぎってきたが、警告しておかなければならない。Claudeは、**非常に複雑で不規則なベクターイラスト**（完全な人物画など）を扱う場合、完全に脳死状態になる。
何千行もの `<path>` を書き出し、ブラウザはスライドショーのように重くなり、最終的な結果はピカソの初期の作品のようになるだろう。抽象的すぎて何なのかすらわからない。

だから、これだけは覚えておいてくれ：
1. **絶対にAIに人間の顔を描かせるな。** ホラーゲームの素材を集めているのでない限り。
2. **幾何学的な図形、チャート、UIコンポーネント、シンプルなロゴ、アイコンに集中しろ。** これが奴のスイートスポットだ。
3. **問題に直面したら、要件を分解しろ。** 宇宙を一度に描けと頼むな。まず太陽を描かせ、次に地球を描かせろ。

要するに、正気を保てということだ。AIはツールであり、万能薬ではない。
