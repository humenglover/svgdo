## SVG는 그냥 이미지가 아니다

많은 사람들이 SVG를 img 태그에 넣고 끝낸다. 그러나 img 안의 SVG는 죽어 있다. 내부 요소에 접근할 수도 없고, path에 클릭 이벤트를 달 수도 없다. SVG를 살리려면 HTML에 인라인으로 넣어야 한다.

인라인으로 넣으면 SVG의 모든 요소는 진짜 DOM 노드가 된다. querySelector로 가져오고, addEventListener로 이벤트를 달고, setAttribute로 속성을 바꿀 수 있다. 이것이 모든 것의 기반이다.

## 1단계: 모든 요소에 ID 부여하기

인터넷에서 받은 SVG나 디자이너가 Figma에서 내보낸 파일의 요소들은 대부분 ID가 없거나, 있어도 "레이어 1 복사본 3" 같은 중복 투성이다. 인터랙션을 하려면 먼저 각 요소에 고유 식별자를 부여해야 한다.

SVG를 파싱하고 DOM 트리를 순회하면서 조작 가능한 모든 요소(path, rect, circle, ellipse, polygon, line, g)에 data-editor-id를 주입한다. 동시에 각 요소의 속성(fill, stroke, d 등)을 배열에 수집해 나중에 속성 패널에 사용한다.

defs, clipPath, mask 내부의 요소는 건드리지 말 것. 이것들은 렌더링 정의용이지 사용자가 조작하는 도형이 아니다. g 요소는 많은 SVG가 transform을 g에 붙이므로 포함해야 한다.

## 2단계: 클릭 선택, 생각보다 까다롭다

인라인 SVG 요소는 클릭 이벤트를 네이티브로 지원한다. 함정은 이벤트 버블링에 있다. path를 클릭하면 부모 g, 더 바깥쪽 svg로 버블링된다. svg에도 선택 해제용 클릭을 달아놓았다면 방금 선택한 요소가 즉시 해제된다.

해결책: 요소 핸들러에서 stopPropagation을 호출한다. 선택 로직을 svg 레벨에 두지 않는다.

또한 stroke-width가 1px인 가느다란 path는 클릭하기 어렵다. 선택된 요소 주변에 투명한 버퍼 영역(약 10px)을 두어 해결한다.

## 3단계: 드래그, 모든 것은 좌표에 달렸다

드래그 동작 자체는 간단하다. pointerdown으로 시작점을 기록하고, pointermove로 델타를 계산하며, pointerup으로 확정한다. 어려운 건 좌표다.

마우스 위치는 화면 좌표계에 있지만 SVG 요소는 SVG 좌표계에 산다. 이 관계는 viewBox, 현재 줌 레벨, 부모 그룹의 transform에 따라 결정된다. 화면 좌표의 델타를 그대로 사용하면 요소가 엉뚱한 방향으로 날아간다.

올바른 방법: 매 pointermove마다 getScreenCTM으로 현재 변환 행렬을 가져와서 마우스의 화면 좌표를 SVG 내부 좌표로 변환한 후 델타를 계산한다.

중첩 그룹에서 꽤 오래 헤맸다. path가 서너 겹의 g 안에 있고 각 g가 저마다 transform을 가지고 있을 수 있다. 요소의 직계 부모 CTM을 사용해야 한다. svg 루트의 CTM이 아니다.

## 4단계: 하이라이트, 세 가지 방법

**색상 변경.** 요소를 선택하면 stroke를 검정에서 파랑으로 바꾼다. 문제는 선택 해제 시 원래 색상을 몰라서 되돌릴 수 없다는 점이다.

**CSS 필터 사용.** filter: drop-shadow로 선택 요소를 감싼다. 원본 속성은 전혀 건드리지 않는다. 해제 시 filter만 제거한다.

**오버레이 방식.** SVG 위에 절대 위치 div를 겹쳐 놓고 getBoundingClientRect로 선택 요소의 위치를 구해 점선 사각형을 그린다. 오버레이는 SVG 좌표계 바깥에 있으므로 줌의 영향을 받지 않는다.

## 5단계: 속성 편집, style 우선순위를 조심하라

선택 후 사용자가 fill이나 stroke를 변경하려 할 때 단순히 setAttribute하면 될 것 같다. 그러나 Figma 출력 SVG는 스타일이 style 속성 안에 쓰여 있고 style 쪽이 우선된다.

style="fill: red"가 있는 요소에 setAttribute('fill', 'blue')를 해도 아무 변화도 없다. 먼저 style 안을 확인하고 해당 프로퍼티가 있으면 style에서 제거한 후 setAttribute한다.

## 6단계: 인터랙티브 플로우차트 만들기

여기까지의 기능이 갖춰지면 플로우차트는 그 위에 비즈니스 로직을 얹기만 하면 된다. 노드는 rect나 circle, 엣지는 path다. 노드 드래그는 해결됐다.

엣지는 노드 이동을 따라가야 한다. 노드-엣지 매핑 테이블을 유지하고 드래그 종료 시 관련 엣지의 d 속성을 재계산한다. 엣지 클릭은 이중 레이어로 해결한다. 투명한 굵은 path가 클릭 담당, 보이는 가는 path가 표시 담당.

이 모든 것을 쌓아 올리면 쓸 만한 SVG 에디터가 된다. svgdo.com의 에디터도 이 방식으로 구현되어 있다. GitHub에 오픈소스로 공개 중.
