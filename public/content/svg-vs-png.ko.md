## 벡터 vs 래스터: 이 논쟁은 끝내야 합니다

![Article Illustration](https://images.unsplash.com/photo-1550751827-4bd374c3f58b?w=1200&q=80)

"SVG를 써야 할까요, PNG를 써야 할까요?" — 디자이너와 개발자 모두가 직면하는 질문입니다.

대답은 흑백이 아닙니다. 각 형식마다 최적의 사용 사례가 있습니다.

---

## 주요 차이점 한눈에

| 관점 | SVG | PNG |
|------|-----|-----|
| 이미지 유형 | 벡터(수식) | 래스터(픽셀) |
| 확대/축소 | 무한, 무손실 | 확대 시 흐림 |
| 파일 크기 | 단순 도형에서 극소 | 해상도에 비례 |
| 투명도 | 네이티브 지원 | 네이티브 지원 |
| 애니메이션 | CSS/JS/SMIL | APNG만 |
| SEO | 텍스트 색인 가능 | alt 텍스트 필요 |

---

## SVG를 사용해야 할 때

- **아이콘과 UI 요소** — SVG의 진정한 강점
- **데이터 시각화** — ECharts, D3.js 등은 내부적으로 SVG
- **반응형 디자인** — 하나의 SVG 파일이 모든 해상도에서 작동
- **인터랙티브 요소** — 호버 색상 변경, 클릭 애니메이션

## PNG를 사용해야 할 때

- **사진과 실제 이미지** — 연속적인 색상 그라데이션은 SVG로 재현 불가
- **복잡한 그라데이션과 그림자** — SVG 코드가 비대해짐
- **레거시 브라우저** — IE11 이전 지원이 필요한 경우(현재는 드묾)

SVG 에디터에서 SVG와 PNG를 언제든지 변환할 수 있습니다 — SVG를 업로드하고 원하는 해상도로 PNG로 내보내세요.
