# 아이콘 디자인 가이드: SVG로 시작하는 완벽한 워크플로 (아무렇게나 선 긋기 중단)

솔직히 수많은 레거시 코드베이스를 넘겨받으면서 저를 가장 미치게 만드는 것은 `<img>` 태그의 남용뿐만 아니라 어떠한 표준화도 부족한 SVG 아이콘들입니다.

가끔 프로젝트의 assets 폴더를 열어보면 그 안의 아이콘들은 혼돈 그 자체입니다. 어떤 것은 24x24이고 어떤 것은 200x200입니다. 선 두께가 1px인 것도 있고 1.5px인 것도 있습니다. `fill`에 `#333`이 하드코딩된 것도 있고 8겹의 `<g>` 그룹으로 둘러싸인 것도 있습니다. 프로덕트 매니저가 "이 아이콘들에 다크 모드를 추가해 주세요"라고 말할 때마다 프론트엔드 엔지니어들은 그 자리에서 사표를 내고 싶어 합니다.

SVG는 디자인과 코드 사이의 다리입니다. 진정으로 뛰어난 아이콘 세트는 단순히 "보기 좋은" 것 이상이어야 합니다. 엔지니어링 수준에서 엄격하고 제어 가능해야 합니다. 오늘 우리는 모호한 미학적 디자인에 대해 이야기하지 않을 것입니다. 가장 하드코어한 기본 사양부터 시작하여 엔터프라이즈급 SVG 아이콘을 실제로 어떻게 그리고, 관리하고, 사용해야 하는지 논의할 것입니다.

---

## 1. 아트보드를 버리고 "픽셀 그리드"부터 구축하라

Figma에서 무심코 상자를 드래그해서 아이콘을 그리기 시작하는 디자이너가 얼마나 많은지 모릅니다. 이것은 절대적인 금기 사항입니다.

뛰어난 UI 아이콘은 절대적으로 엄격한 픽셀 그리드를 기반으로 해야 합니다. 현재 업계에서 가장 보편적인 표준은 **24x24** viewBox입니다. 바늘을 그리든 코끼리를 그리든 최종 생성된 코드는 다음과 같아야 합니다.

```html
<svg viewBox="0 0 24 24" width="24" height="24">
```

### 키라인(Keylines) 및 패딩
24x24 아트보드 내에서 내용을 가장자리까지 꽉 채우지 마십시오! 최소 2px의 안전 여백(패딩)을 남겨 두어야 하므로 실제 드로잉 영역은 20x20에 불과합니다.
왜 그럴까요? 모서리가 둥근 직사각형을 원 옆에 배치할 때 같은 픽셀 면적이 주어지면 원이 시각적으로 더 작아 보이기 때문입니다. 화면에서 같은 크기로 보이게 하려면 이 2px 안전 영역을 사용하여 원을 약간 확대해야 합니다(20x20 제한을 깨고 22x22에 도달). 이것을 우리는 "광학적 균형(Optical Balance)"이라고 부릅니다.

![분할 뷰(Split View)에서 viewBox 및 SVG 소스 코드 실시간 확인](/content/images/icon-split-view.png)

*우리의 SVG 에디터를 사용할 때, 코드 분할 뷰 모드로 직접 전환하고 첫눈에 `viewBox`가 정확히 0 0 24 24인지 확인해야 합니다. 그렇지 않다면 초기 단계에서 다시 작업하도록 돌려보내십시오.*

## 2. 스트로크(선) 사양: 악마는 디테일에 있다

시스템 아이콘이 선형(Linear) 스타일인 경우 **선 두께가 균일해야 합니다**.

24x24 아이콘의 경우 **2px 선**은 거의 모든 주요 거대 기술 기업(Apple, Google, Microsoft)이 인정하는 황금 비율입니다. 1px는 레티나가 아닌 화면에서 너무 희미해 보이고, 1.5px는 특정 저해상도 디스플레이에서 서브 픽셀 렌더링 문제(흐릿함)를 일으킵니다.

```html
<path d="..." stroke-width="2" stroke-linecap="round" stroke-linejoin="round"/>
```

또한 둥근 끝점(`stroke-linecap="round"`)과 둥근 결합점(`stroke-linejoin="round"`)을 사용하는 것이 강력히 권장됩니다. 이들은 낮은 해상도에서 벡터 그래픽이 나타내기 쉬운 계단 현상을 크게 상쇄하여 아이콘을 훨씬 부드럽고 친근하게 보이게 합니다.

가장 중요한 것: **섞어 쓰지 마십시오!** 프로젝트에 1.5px 검색 아이콘과 2px 홈 아이콘이 동시에 있어서는 안 됩니다. 이러한 시각적 불연속성은 전체 애플리케이션의 프리미엄 느낌을 즉시 저하시킵니다.

## 3. 색상 관리: currentColor가 유일한 진정한 신이다

이곳은 프론트엔드 개발자와 디자이너 사이의 주요 분쟁 구역입니다. 디자이너가 내보낸 SVG에는 `#000000`이나 훨씬 더 기이한 색상 값이 포함되어 있는 경우가 많습니다.

SVG의 색상이 하드코딩되어 있으면 프론트엔드 개발자가 CSS를 통해 호버 상태나 다크 모드를 제어하기가 극도로 고통스러워집니다(일반적으로 무리하게 색상을 변경하기 위해 못생긴 CSS 필터를 사용하도록 강요받음).

**유일한 모범 사례: 기본 색상을 `currentColor`로 교체하십시오.**

```html
<!-- 잘못된 방법 -->
<svg fill="none" stroke="#333333">

<!-- 올바른 방법 -->
<svg fill="none" stroke="currentColor">
```

`currentColor`를 사용함으로써 SVG는 텍스트처럼 작동하여 상위 요소의 `color` 속성을 자동으로 상속합니다. 외부 래퍼에 `color: red;`를 작성하면 아이콘이 빨간색으로 변합니다. 다크 모드에서 텍스트가 흰색으로 변하면 아이콘도 자동으로 흰색으로 변합니다. 깔끔하고 우아하며 성능 오버헤드가 전혀 없습니다.

## 4. 부드러운 "WYSIWYG" 워크플로를 철저히 경험하라

말은 쉽습니다. 기술적 배경이 없는 디자이너가 코드 수준의 사양을 완전히 준수하도록 강제하는 것은 어려운 경우가 많습니다. 이를 위해서는 프론트엔드 개발자가 이러한 SVG를 "정리"하고 "미리 보기"할 수 있는 매우 편리한 워크플로가 필요합니다.

우리는 믿을 수 없을 정도로 강력한 워크플로를 SVG 에디터에 직접 구축했습니다. 아래에서 순수하게 로컬에서 녹화된 실시간 데모 애니메이션을 볼 수 있습니다(이것은 외부 링크된 네트워크 이미지가 아닙니다. 로컬 환경에서 바로 부드럽게 로드됩니다).

![SVG 아이콘 가져오기, 코드 정리, 초고속 내보내기의 완전한 워크플로 데모](/content/images/icon-workflow-demo.webp)

애니메이션에서 볼 수 있듯이 라이브러리에서 표준을 준수하는 아이콘을 원클릭으로 추출하거나 지저분한 소스 파일을 던져 넣을 수 있습니다. 왼쪽 패널의 컨트롤을 사용하여 **Split View**(분할 뷰)로 직접 전환합니다. 시각적 미리 보기를 보면서 중복되는 `<g>` 태그, 쓸모없는 `<defs>`, 하드코딩된 색상이 있는 가비지 코드를 무자비하게 삭제할 수 있습니다. 확인이 끝나면 한 번의 클릭으로 Export(내보내기)를 누릅니다.

IDE와 브라우저 사이를 계속 탭하며 이동할 필요가 없습니다. 이것이 최신 프론트엔드 개발자가 벡터 자산을 처리할 때 가져야 할 효율성입니다.

## 결론: 당신만의 체크리스트를 구축하라

다음에 SVG 아이콘 배치(batch)를 받으면 서둘러 코드에 던져 넣지 마십시오. 다음 체크리스트를 확인하십시오.

1. **균일한 치수:** 모든 viewBox가 `0 0 24 24`입니까?
2. **일관된 선 두께:** 선 두께가 균일하게 `2px`(또는 설정한 기준)입니까?
3. **색상 상속:** 하드코딩된 모든 색상이 `currentColor`로 교체되었습니까?
4. **코드 순도:** Figma에서 생성된 중복 태그와 가비지 코드가 압축되고 정리되었습니까?

모두 통과했다면 축하합니다. 당신의 애플리케이션은 디테일 측면에서 이미 조잡하게 만들어진 프로젝트의 80%를 넘어섰습니다. 표준은 지루할 수 있지만, 엔지니어링이 지속 가능하게 진화할 수 있도록 하는 유일한 기반입니다.
