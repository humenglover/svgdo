# Figma의 수출 난장판과 작별하기: AI와 로컬 편집기를 사용하여 SVG 개발을 마스터한 방법

솔직히 여러분은 어떨지 모르겠지만 프런트엔드 개발을 하거나 기술 블로그를 쓸 때 '일러스트레이션'을 제대로 만드는 것은 언제나 악몽입니다.

간단한 아키텍처 다이어그램, 워크플로 차트 또는 기술적인 배경 장식이 필요할 때마다 고군분투하기 시작합니다. 스톡 이미지를 찾으면 내 콘텐츠에 완벽하게 맞는 것을 찾기가 어렵고 때로는 저작권 문제가 발생하기도 합니다. 직접 그리자니 Illustrator나 Sketch를 여는 것은 호두를 까기 위해 대형 해머를 사용하는 것 같습니다. 물론 많은 사람들이 Figma를 사용하고 Figma는 훌륭합니다. 하지만 Figma에서 디자인을 순수 SVG 코드로 내보내 본 적이 있습니까? 일반적으로 쓸모없는 `<g>` 태그, 절대 위치 지정 및 매우 중복되는 경로로 가득 차 있습니다. 그것을 웹 페이지에 떨어뜨리면 지저분해 보일 뿐만 아니라 파일 크기조차 그렇게 작지 않습니다.

SVG 코드를 전적으로 손으로 작성하는 것에 관해서는... `<rect>` 또는 `<circle>`을 작성할 수 있다는 것은 인정하지만 부드러운 베지어 곡선으로 화살표를 손으로 코딩하거나 그림자가 있는 복잡한 그래디언트를 만들라고 하면 말 그대로 그 자리에서 쓰러질 것입니다.

프런트엔드 생산성을 완전히 해방시키는 놀라운 트릭을 발견한 것은 대형 언어 모델(특히 Claude 및 DeepSeek의 플래그십 시리즈와 같이 강력한 코딩 및 공간 추론 기능을 갖춘 차세대 모델)의 등장과 함께 비교적 최근이었습니다. <strong>AI를 사용하여 SVG의 스켈레톤 초안을 생성한 다음 `svg-editor`에 직접 던져 넣어 미세 조정을 "블라인드 스나이프"하고 실시간으로 렌더링합니다.</strong>

오늘 기사에서는 믿을 수 없을 정도로 만족스러운 이 워크플로를 여러분과 공유하려고 합니다. 순수한 실용적인 지식과 대역폭을 극도로 절약합니다.

## AI 그리기에 대한 우리의 오해

많은 사람들이 "AI 그리기"라는 말을 들었을 때 가장 먼저 생각하는 것은 Midjourney, DALL-E 또는 Stable Diffusion입니다. 의심할 여지 없이 이러한 확산 모델에서 생성된 비트맵 이미지는 절대적으로 훌륭하고 디테일이 풍부합니다. 그러나 극단적인 성능을 추구하는 웹 개발자이거나 수정처럼 맑은 다이어그램이 필요한 블로거라면 비트맵에 치명적인 결함이 있음을 깨닫게 될 것입니다.

첫 번째는 <strong>파일 크기</strong>입니다. 고화질 다이어그램은 쉽게 수백 KB 또는 몇 MB가 될 수 있습니다. 기사에 이미지가 10개 있는 경우 사용자의 로드 경험이 끔찍할 것입니다. 두 번째는 <strong>불변성</strong>입니다. Midjourney를 사용하여 아름다운 UI 모형을 생성하지만 내부의 영어 단어 철자가 틀리거나 버튼을 파란색에서 초록색으로 바꾸려면 죄송합니다. "블라인드 박스"를 여는 것처럼 완전히 다시 생성할 수밖에 없습니다. 정확한 제어를 달성하기는 매우 어렵습니다. 마지막으로 <strong>크기 조절 왜곡</strong>이 있습니다. 해상도가 다른 화면에서 비트맵은 완벽하게 선명한 상태를 유지하는 데 어려움을 겪습니다.

이것이 바로 SVG(Scalable Vector Graphics)의 장점이 빛나는 곳입니다. 순수한 텍스트 코드이며 자연스럽게 품질 저하 없이 무한한 확장을 지원하고 파일 크기는 애처로울 정도로 작습니다. SVG로 표현된 매우 복잡한 차트는 2KB에 불과할 수 있습니다.

그렇다면 AI가 Python과 React를 작성할 수 있으므로 나를 위해 직접 SVG 코드를 작성할 수 있을까요?

대답은 이전에는 할 수 없었지만 지금은 절대적으로 할 수 있다는 것입니다. 초기 모델은 HTML 구문을 이해했지만 "공간적 직관"이 심각하게 부족했습니다. 그들이 생성한 요소는 종종 비뚤어지고 텍스트가 테두리와 겹쳐 읽을 수 없었습니다. 하지만 오늘날의 최고 계층 모델은 다릅니다. 그들은 좌표계가 무엇인지 알거나 `viewBox`의 목적을 이해할 뿐만 아니라 색상 이론과 기본적인 타이포그래피 미학까지도 이해합니다.

## 실제 워크플로: "구조화된 프롬프트"에서 초안까지

AI가 신뢰할 수 있는 SVG 코드를 작성하도록 하려면 Midjourney에서처럼 단순히 많은 형용사를 던져서는 안 됩니다. 개발자의 사고방식을 사용하고 "구조화된 프롬프트"를 제공해야 합니다.

저는 보통 다음과 같은 템플릿을 사용하여 AI를 제한합니다.

1. <strong>역할 설정</strong>: "귀하는 10년 경력의 수석 프런트엔드 데이터 시각화 전문가이자 UI 디자이너입니다." (이렇게 하면 코드 품질 및 타이포그래피 미학과 관련된 모델의 가중치가 활성화됩니다).
2. <strong>핵심 목표</strong>: "내 기사를 위해 [워크플로 다이어그램]을 그릴 때 순수 SVG 코드를 사용하세요."
3. <strong>캔버스 제한</strong>: "viewBox를 0 0 1000 400으로 설정합니다. 배경에는 따뜻한 회백색 또는 프리미엄 어두운 그래디언트를 사용합니다."
4. <strong>엄격한 규칙</strong>(이것이 가장 중요한 단계입니다): "그래픽과 텍스트가 겹치는 것을 엄격히 금지합니다. 텍스트는 충분한 패딩과 함께 중앙에 정렬되어야 합니다. 그래픽을 연결하려면 점선 화살표를 사용하세요."
5. <strong>출력 형식</strong>: "설명 없이 `<svg>` 태그 코드를 직접 출력하고 마크다운 코드 블록으로 줄 바꿈하지 마세요."

이러한 프롬프트를 Claude나 DeepSeek에 던지면 종종 기적이 일어납니다. 10여 초 안에 때로는 완벽하게 깔끔한 들여쓰기가 있는 구조적으로 명확한 SVG 코드가 눈앞에 나타날 것입니다.

## 로컬 `svg-editor`가 절대적으로 필요한 이유

아마 이렇게 물을 것입니다. AI가 이미 코드를 작성했으니 복사해서 내 프로젝트에 붙여넣으면 안 될까?

<strong>절대 안 됩니다.</strong>

이것이 이 워크플로에서 가장 현실적이고 쉽게 간과되는 "함정"입니다. AI는 결국 AI입니다. 자신이 생성하는 이미지를 "볼 수 있는" 진짜 눈이 없습니다. 좌표를 계산하기 위해 전적으로 수학적 확률에 의존합니다. 따라서 다음과 같은 사소한 문제가 자주 발생하게 됩니다.

- AI가 직사각형의 `width`를 100으로 설정하지만 생성하는 텍스트는 12개 단어이므로 텍스트가 직사각형의 테두리를 벗어나게 됩니다.
- AI가 선택하는 임의의 색상은 색상 스펙트럼에서는 올바를 수 있지만 실제 화면에서는 믿을 수 없을 정도로 거슬리게 보입니다.
- AI는 `<svg width="1000" height="400">`과 같은 절대값을 하드코딩하여 모바일 장치에서 반응형으로 축소할 수 없도록 만들 수 있습니다.

이러한 사소한 문제 중 하나를 발견할 때마다 되돌아가 AI에게 "왼쪽 상자의 텍스트 글꼴을 작게 만들어"라고 요구한다면, AI는 그 작은 요청 하나를 충족시키기 위해 전체 코드를 재생성할 가능성이 매우 높으며 갑자기 원래 완벽했던 오른쪽 절반이 엉망이 됩니다. 이 "머리카락 하나를 당겨 온몸을 움직이게 하는" 시나리오의 커뮤니케이션 비용은 엄청나게 높습니다.

<strong>이것이 제가 이 사이트에서 제공하는 `svg-editor`에 강하게 의존하는 이유입니다.</strong>

AI는 복잡한 노드, 그림자 필터(`feDropShadow`) 및 그래디언트(`linearGradient`)를 모두 구축하여 "0에서 1로" 이동하는 힘든 작업을 처리합니다. 한편 당신은 우리의 `svg-editor`를 사용하여 "99에서 100"까지 미세한 다듬기를 완료하기만 하면 됩니다.

AI가 생성한 모든 코드를 편집기 왼쪽에 있는 코드 영역에 버릴 수 있습니다. 즉시 오른쪽의 실시간 미리보기 창에서 코드가 가시적인 그래픽으로 바뀝니다.

![편집기에서 워크플로 SVG를 디버깅하는 실제 시나리오](/content/images/ai-svg-generation-workflow.png)

위의 워크플로 다이어그램을 예로 들어보겠습니다. AI가 처음 생성했을 때 세 개의 둥근 직사각형 사이의 거리가 약간 너무 가까워서 혼잡해 보였습니다. 그것을 조정하기 위해 내가 AI로 돌아갔다면 어떤 혼란을 일으킬지 신만이 알 것입니다. 하지만 `svg-editor`에서는 오른쪽 미리보기를 계속 주시하면서 왼쪽에서 두 번째 도형의 `x` 좌표를 `400`에서 `500`으로 수동으로 변경하기만 했습니다. 내가 키보드를 치는 순간 도형은 오른쪽으로 100픽셀 얌전하게 변환되었습니다. 이 WYSIWYG 안보와 통제감은 순수한 AI 대화가 결코 줄 수 없는 것입니다.

## 고급 플레이: 순수 코드로 "컬러 신문" UI 렌더링하기

건조한 흐름도를 그리는 것 외에도 좀 더 예술적인 것을 만들 수 있습니다. 예를 들어 가끔 기술 요약을 작성할 때 레트로 서양풍의 "컬러 신문" 또는 "인디 잡지" 스타일의 일러스트레이션을 원할 때가 있습니다.

스톡 사진 사이트에서 검색하면 "코드와 같은" 느낌의 디자인을 찾기가 어려울 뿐만 아니라 구독료를 지불해야 합니다. 하지만 내가 해야 할 일은 AI에 대한 프롬프트를 변경하는 것뿐입니다.

> "SVG를 사용하여 잡지 스타일의 기능 소개 카드를 그리세요. 맨 위에는 'THE DAILY OBSERVER'라고 적힌 크고 굵은 Serif 텍스트가 있어야 합니다. 본문에는 다양한 색상(예: 밝은 노란색, 연한 파란색, 분홍색)의 대비가 높은 직사각형 블록 세 개가 있어야 하며 테두리는 인쇄 질감을 모방하기 위해 두껍고 어두운 실선이어야 합니다."

코드를 받으면 편집기에 무심코 던져 넣습니다. 이 시점에서 나는 AI가 선택한 노란색이 약간 칙칙하다는 것을 알게 됩니다(`#eab308`). 코드에서 직접 밝은 노란색(`#fef08a`)으로 변경하고 편리하게 테두리의 `stroke-width`를 1에서 3으로 변경합니다.

디버깅 프로세스 전체가 웹 기반 "색칠 게임"을 하는 것처럼 느껴지며 스트레스 해소에 엄청난 도움이 됩니다.

![svg-editor에서 실시간으로 타이포그래피 및 색상 조정](/content/images/ai-svg-generation-newspaper-style.png)

세심하게 형식이 지정되고 색상이 선명하며 그림자와 격자선으로 완성된 위 사진이 본질적으로 2KB 미만의 순수 텍스트 문자열에 불과하다는 것을 상상할 수 있습니까? 내 말을 믿지 않는다면 지금 바로 브라우저의 요소를 마우스 오른쪽 버튼으로 클릭하여 확인하고 로드 속도가 얼마나 빠른지 확인하세요!

## 궁극의 킬러 무기: 리버스 엔지니어링 (그래픽 독립성 훔치기)

나만 알고 있는 "사악하지만" 아주 유용한 비법 하나를 공개하겠습니다. 바로 <strong>역재생산</strong>입니다.

보통 Twitter(X)를 스크롤하거나 상위 개발자의 블로그를 읽을 때 빛나는 효과가 있는 믿을 수 없을 정도로 아름다운 다크 모드 시스템 아키텍처 다이어그램을 자주 보게 됩니다. 이런 일이 발생하면 스크린샷을 찍어 저장한 다음 시각 기능이 있는 대형 모델(예: Claude 3.5 Sonnet의 다중 모달 버전)에 공급하기만 하면 됩니다.

"<strong>이 이미지의 타이포그래피 레이아웃과 색상 논리를 분석하고 기본 SVG 코드를 사용하여 1:1로 완벽하게 복제하십시오.</strong>"라는 매우 간단한 프롬프트와 쌍을 이루십시오.

AI는 무자비한 코드 파서처럼 작동하여 이미지 내의 기하학적 모양과 연결 논리를 즉시 해체하고 구조적으로 동일한 SVG 소스 코드 세트를 손으로 코딩합니다.

물론 텍스트가 아직 다른 사람의 것이기 때문에 이 시점에서는 직접 사용할 수 없습니다. 평소와 같이 코드를 복사하여 우리의 `svg-editor`에 붙여넣으세요. 왼쪽에 코드를 붙여넣으면 오른쪽에 원본 아키텍처 다이어그램이 다시 태어납니다.

다음으로 코드 검색 상자에서 `Ctrl+F`를 누르고 원본 영어 텍스트를 찾아 자체 사본으로 하나씩 바꾸기만 하면 됩니다. 그런 다음 중복된다고 생각되는 여분의 아이콘에 대해 `<path>` 태그가 있는 코드 줄을 삭제하기만 하면 됩니다.

3분도 채 되지 않아 원래 다른 사람 소유였던 딱딱한 비트맵 스크린샷이 워터마크가 없고 무한히 편집할 수 있는 나만의 맞춤형 벡터 그래픽으로 탈바꿈했습니다! Photoshop을 열고 복제 스탬프 도구로 세심하게 수정하는 것보다 이 방법이 훨씬 효율적이지 않나요?

## 결론

그러니 "AI가 발전하면 프로그래머/디자이너는 일자리를 잃을 것"이라는 말도 안 되는 소리를 믿지 마세요. AI는 당신을 대체하기 위해 온 것이 아닙니다. 당신의 "초급 슬라이서"이자 "코드 포터"가 되기 위해 온 것입니다.

AI가 복잡한 SVG 태그를 작성하는 문턱을 넘으면 진정으로 여러분을 제한하는 것은 도구의 숙련도와 미적 취향뿐입니다. 그리고 우리의 `svg-editor` 도구는 이 워크플로에서 가장 중요한 누락된 부분을 완벽하게 채웁니다. <strong>당신에게 절대적인 통제력을 부여합니다</strong>.

"AI는 영감과 구조를 제공하고 로컬 편집기는 미세 조정과 전달을 완료합니다." 내 생각에 이것이 현 시대의 가장 우아하고 효율적이며 대역폭을 절약하는 벡터 그래픽 개발 패러다임입니다.
