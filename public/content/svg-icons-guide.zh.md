# 图标设计指南：从 SVG 开始的完整工作流（别再乱画线了）

说实话，接手过那么多祖传代码库，最让我抓狂的不仅是乱用 `<img>` 标签，还有那些毫无规范可言的 SVG 图标。

有时候你打开一个项目的 assets 文件夹，里面的图标简直是群魔乱舞：有的图标是 24x24 的，有的是 200x200 的；有的线宽是 1px，有的是 1.5px；有的颜色是写死在 `fill` 里的 `#333`，有的则是在外面套了八层 `<g>` 分组。每次产品经理说“给这些图标加个深色模式”的时候，前端工程师都想原地辞职。

SVG 是设计和代码的桥梁。一个真正优秀的图标集，不只是“看起来好看”那么简单，它必须在工程上是严谨的、可控的。今天，我们不谈那些虚无缥缈的美学设计，直接从最硬核的底层规范讲起，聊聊一套企业级 SVG 图标到底该怎么画、怎么管、怎么用。

---

## 1. 扔掉你的画板，先建个“像素网格”

不知道有多少设计师喜欢随手在 Figma 里拉一个框就开始画图标。这是绝对的禁忌。

优秀的 UI 图标必须基于绝对严谨的像素网格。目前行业内最通用的标准是 **24x24** 的 viewBox。不管你画的是一根针还是一头大象，最后生成的代码必须是：

```html
<svg viewBox="0 0 24 24" width="24" height="24">
```

### 关键线（Keylines）与留白
在 24x24 的画板里，绝对不要把内容塞满！你需要留出至少 2px 的安全内边距（Padding），所以实际绘制区域只有 20x20。
为什么？因为当你需要把一个圆角矩形和一个圆形放在一起时，同等像素面积下，圆形在视觉上会显得更小。你需要利用这 2px 的安全区，把圆形稍微放大一点点（突破 20x20 的限制，达到 22x22），这样它们在屏幕上看起来才会是一样大的。这就是所谓的“光学平衡”。

![在 Split View 下实时检查 viewBox 和 SVG 源码](/content/images/icon-split-view.png)

*你在使用我们的 SVG 编辑器时，直接切到代码分栏模式，第一眼就得检查 `viewBox` 是不是规规矩矩的 0 0 24 24。如果不是，趁早打回去重做。*

---

## 2. 描边规范：细节里的魔鬼

如果你的系统图标是线性风格的，那么**描边宽度（Stroke Width）必须统一**。

对于 24x24 的图标，**2px 描边** 是几乎所有大厂（苹果、谷歌、微软）公认的黄金比例。1px 会在非视网膜屏幕上显得太虚，1.5px 在某些低分辨率屏幕上会出现亚像素渲染问题（发虚）。

```html
<path d="..." stroke-width="2" stroke-linecap="round" stroke-linejoin="round"/>
```

另外，强烈建议使用圆角端点（`stroke-linecap="round"`）和圆角转角（`stroke-linejoin="round"`）。它们能大幅抵消矢量图形在低分辨率下容易出现的锯齿感，让图标看起来更加平滑、友好。

最重要的是：**别混用！** 你的项目里不能同时存在 1.5px 的搜索图标和 2px 的主页图标，这种视觉断层会瞬间拉低整个应用的高级感。

---

## 3. 颜色管理：currentColor 是唯一的真神

这是前端和设计冲突的重灾区。设计师导出的 SVG 经常带有 `#000000` 或者更奇葩的颜色值。

如果 SVG 里的颜色是写死的，前端通过 CSS 控制 Hover 态或深色模式就会极其痛苦（通常只能用丑陋的 CSS Filter 暴力变色）。

**唯一的最佳实践：将主要颜色替换为 `currentColor`。**

```html
<!-- 错误做法 -->
<svg fill="none" stroke="#333333">

<!-- 正确做法 -->
<svg fill="none" stroke="currentColor">
```

使用了 `currentColor` 后，SVG 就会像文字一样，自动继承其父元素的 `color` 属性。你在外层写一个 `color: red;`，图标就跟着变红。深色模式下把文字变白，图标也就自动变白。清爽、优雅、零性能损耗。

---

## 4. 彻底体验顺滑的“所见即所得”工作流

光说不练假把式。很多时候，你很难要求非技术出身的设计师完全遵守代码层面的规范。这就需要前端开发者有一个极度顺手的工作流来“清洗”和“预览”这些 SVG。

我们在 SVG 编辑器里内置了一个极其强悍的工作流，你可以看看下面这个纯本地录制的实机演示动画（绝非外链网图，直接本地顺滑加载）：

![SVG 图标从导入、代码清理到极速导出的完整工作流演示](/content/images/icon-workflow-demo.webp)

正如动图里演示的，你可以一键从图标库中提取标准规范的图标，或者把你那乱七八糟的源文件扔进去。通过左侧面板的控件，直接切到 **Split View**，你可以一边看着视觉预览，一边手起刀落删掉那些冗余的 `<g>` 标签、多余的 `<defs>`、以及带有绝对颜色的垃圾代码。确认无误后，一键 Export 即可。

不需要每次都在 IDE 和浏览器之间切来切去，这才是现代前端开发者处理矢量资产应有的效率。

---

## 结语：建立你的检查清单

下次再拿到一组 SVG 图标时，别急着往代码里扔。走一遍这个清单：

1. **尺寸统一：** viewBox 是否全都是 `0 0 24 24`？
2. **线宽一致：** 描边是否统一为 `2px`（或你设定的其他标准）？
3. **颜色继承：** 所有的写死颜色是否都已经替换为 `currentColor`？
4. **代码纯净：** 冗余的标签、Figma 生成的废代码是否已经压缩清理完毕？

如果都符合，恭喜你，你的应用在细节上已经超越了 80% 的粗制滥造项目。规范虽然繁琐，但它是让工程持久演进的唯一基石。
