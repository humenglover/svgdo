# SVG 애니메이션의 피, 땀, 눈물: 초보자부터 키보드를 박살낼 뻔하기까지

솔직히 이 글을 쓰는 지금, 저는 문자 그대로 레거시 코드베이스에서 또 다른 SVG 애니메이션 버그를 수정하는 중입니다. 제자리에서 조용히 돌아야 할 로딩 원이 브라우저 왼쪽 상단 모서리를 이상한 원심력 궤도로 돌다가 화면 밖으로 완전히 날아가 버리는 것을 모니터로 빤히 쳐다보고 있습니다.

지금 제 정확한 기분은 아래 GIF에 완벽하게 담겨 있습니다.

![내 SVG 아이콘이 화면 밖으로 날아가는 것을 보는 기분](/content/images/this-is-fine-css.gif)
*(이것이 말 그대로 프론트엔드 엔지니어의 일상입니다. 세상은 불타고 있는데, 나는 여전히 CSS나 만지작거리고 있죠.)*

저와 같은 분이 얼마나 될지 모르겠지만, 처음 프론트엔드를 배우기 시작했을 때 저는 CSS 애니메이션이 그저 `@keyframes` 몇 개 찰싹 붙이는 건 줄 알았습니다. `transform: rotate(360deg)` 쓰는 법 모르는 사람이 어딨습니까? 일반 HTML `div`나 `span`을 애니메이션하는 건 눈 감고도 할 수 있는 일입니다. 하지만! 특정 `<path>`나 `<circle>`을 독립적으로 움직이게 하려고 하는 등 SVG 안의 노드에 손을 대는 순간 절대적인 악몽이 시작됩니다.

오늘, 저는 단순한 애니메이션 하나 때문에 StackOverflow를 반나절이나 뒤져야 하는 좌절감에 완전히 질려버렸습니다. 지난 몇 년 동안 SVG 애니메이션에서 겪었던 모든 함정을 수작업으로 쏟아내기로 결심했습니다. 헛소리나 딱딱한 "첫째, 둘째, 마지막으로" 같은 구조는 빼고 말이죠. 그냥 고통에 대해서만 이야기합시다.

SVG 애니메이션을 만들기 위해 JavaScript를 사용하여 강압적으로 DOM을 조작하고 있다면, 당장 멈추실 것을 강력히 촉구합니다. 그런 쓰레기 코드는 메인 스레드를 질식시켜 죽일 뿐만 아니라 작성한 코드는 길고 냄새가 날 것입니다. 지금이 몇 년도입니까? 휴대폰 화면조차도 120Hz의 주사율을 자랑합니다. 우리에게는 GPU 하드웨어 가속이 필요하고, 궁극의 부드러움이 필요합니다. 따라서 순수 CSS로 인라인 SVG를 구동하는 것이 현재 유일하게 진지하고 렉이 없는 해결책입니다.

하지만 제가 아까 불평했던 것처럼, SVG 노드에 회전 애니메이션을 추가하는 순간 그것은 100% 통제 불능 상태로 날아갑니다. 왜 그럴까요?

우리가 보통 코드를 작성하는 일반 HTML 세계에서는 요소의 `transform-origin`(요소가 변형되거나 회전하는 중심점)이 기본적으로 정확한 중심, 즉 `50% 50%`로 설정되기 때문입니다.
하지만 SVG 세계에는 믿을 수 없을 정도로 기괴한 좌표계가 있습니다! 대부분의 브라우저(특히 Safari, 딱 집어서 말합니다)에서 내부 SVG 노드의 변환 원점은 거대한 SVG 캔버스의 왼쪽 상단 모서리 `(0, 0)`에 고정되는 것이 기본값입니다!

이게 얼마나 멍청한 일입니까? 제자리에서 빙그르르 돌고 싶은데 시스템이 3마일 떨어진 시청 광장을 한 바퀴 돌라고 강요하는 것과 같습니다!

저는 언젠가 프로젝트 출시 전날 밤 3시까지 이 문제를 조사하며 깨어있던 적이 있습니다. 결국 구세주는 많은 베테랑들조차 들어본 적 없는 우스꽝스러울 정도로 무명인 CSS 속성이라는 것을 발견했습니다.
회전해야 하는 SVG 노드의 클래스 이름 아래에 다음 두 줄의 코드만 추가하면 됩니다.

```css
.spin-gear {
  transform-origin: center center;
  /* 주목하세요! 이것이 신급 구원자 속성입니다 */
  transform-box: fill-box;
  animation: spin 2s linear infinite;
}
```

`transform-box: fill-box;`를 추가하면 브라우저는 마침내 멍청한 짓을 멈춥니다. 브라우저는 이해합니다. "아, 보스가 저 빌어먹을 거대한 캔버스가 아니라 이 그래픽 자체의 실제 Bounding Box(경계 상자)를 기준선으로 사용하여 중심점을 계산하기를 원하는구나."
이 한 줄의 코드가 빠질 뻔했던 프론트엔드 프로그래머들의 머리카락을 얼마나 많이 구했는지 모릅니다.

회전 외에도 면접에서 허세를 부릴 수 있는 또 다른 화려한 트릭이 "선 그리기 애니메이션(Line Drawing Animation)"입니다.
Apple 공식 웹사이트나 엄청나게 잘난 척하는 미니멀리스트 웹사이트에서 분명히 보셨을 겁니다. 마우스를 스크롤하면 화면의 곡선이 보이지 않는 펜으로 그리는 것처럼 서서히 그려집니다.

많은 사람들이 이것이 대단한 Canvas 라이브러리나 WebGL로 쓰여졌을 거라고 생각합니다. 하지만 사실 이 애니메이션은 SVG에서 순수하게 CSS만을 사용하여 공짜로 얻을 수 있습니다.
근본적인 메커니즘은 괘씸할 정도로 교묘합니다. SVG의 점선(대시) 속성을 이용한 것입니다.

길이가 1000픽셀인 선이 있다고 상상해 보십시오.
첫 번째 단계로 `stroke-dasharray: 1000;`을 사용하여 이 선을 "실선 부분이 1000픽셀 길이이고 빈 간격도 1000픽셀 길이"인 거대한 점선으로 바꿉니다.
두 번째 단계로 `stroke-dashoffset: 1000;`을 강제 적용하여 이 점선을 왼쪽으로 1000픽셀 오프셋합니다. 이렇게 하면 화면의 뷰포트에 들어오는 것은 정확히 그 1000픽셀의 "빈 간격"이 됩니다. 선이 마법처럼 사라진 것입니다.
세 번째 단계로 이 오프셋을 1000에서 0으로 서서히 다시 전환하는 아주 간단한 CSS 애니메이션을 작성합니다.

코드는 이렇게 생겼습니다. 믿기 어려울 정도로 간단하죠.

```css
.magic-line {
  stroke-dasharray: 1000;
  stroke-dashoffset: 1000;
  animation: draw-line 3s ease-in-out forwards;
}

@keyframes draw-line {
  to {
    stroke-dashoffset: 0;
  }
}
```
원래 뷰포트 바깥에 숨어 있던 실선 부분이 천천히 다시 당겨지면서 시각적으로는 바로 그 자리에서 그려지는 것처럼 완벽하게 보입니다. 이 요령만 통달하면 이제부터 회사에 있는 모든 멋진 로딩 애니메이션은 혼자서 다 처리할 수 있습니다.

하지만 그렇다 해도 코드를 작성하는 것은 그냥 코드를 작성하는 것일 뿐입니다. 애초에 받은 SVG가 쓰레기이고, 좌표계가 엉망이며, 의미 없는 `<g>` 태그가 7~8겹이나 중첩되어 있다면 CSS가 아무리 쩔어도 소용이 없습니다. 애니메이션은 무조건 버벅거리고 렉이 걸릴 것입니다.

그러므로 애니메이션을 작성하기 위해 프로젝트에 SVG를 집어넣기 전에 반드시 코드를 먼저 세탁해야 합니다!

광고로 도배된 쓰레기 같은 온라인 압축 사이트는 그만 쓰십시오. 그냥 우리 자체 SVG 에디터를 열고 한번 보십시오. 우리는 완전히 현지화된 워크플로 전체를 구축했습니다. 아래 애니메이션 GIF를 보십시오. 가짜 시각 효과 없이 순수하게 로컬에서 렌더링된, 오직 당신만을 위해 방금 녹화한 것입니다.

디자이너가 여러분에게 던진 온갖 더럽고 지저분한 좌표가 있는 SVG를 집어넣으십시오. Split View(분할 뷰) 아래에서 그 쓸모없는 메타데이터를 직접 삭제하고 viewBox를 정리하십시오. 기본 구조가 깨끗할 때에만 CSS로 작성하는 인터랙티브 애니메이션이 진정으로 60프레임의 매끄러움을 달성할 수 있습니다.

자, 불평은 이쯤 해두죠. 방금 새로운 요구 사항이 들어왔습니다. 프로덕트 매니저가 하트 아이콘을 클릭할 때 통통 튀어야 할 뿐만 아니라 파티클 고리와 함께 폭발해야 한다고 합니다. 저는 또다시 SVG 좌표계와 싸우러 가야 합니다. 그 주문을 기억하십시오. `transform-box: fill-box;`. 다들 칼퇴근하시고 평생 에러 안 만나길 빕니다!
