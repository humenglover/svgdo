# SVG + JS 상호작용: 클릭, 드래그 및 강조 표시 가능한 벡터 그래픽

서버 룸 토폴로지 맵, 극장 좌석 예약 시스템 또는 간단한 온라인 포스터 편집기와 같은 "대화형 그래픽"을 구축하라는 요구 사항을 받았을 때 가장 먼저 드는 생각은 무엇입니까?

많은 사람들의 첫 번째 본능은 "Canvas를 쓰자"이거나 Fabric.js, Konva 등과 같은 방대한 타사 그래픽 라이브러리를 단순히 도입하는 것입니다.

하지만 실제로 <strong>요소의 클릭, 드래그 및 강조 표시</strong>만 구현하면 되는 경우, 순수 JavaScript와 결합된 기본 SVG는 놀랍도록 예리하고 효율적인 무기입니다. SVG는 본질적으로 DOM 그 자체이기 때문에 무거운 종속성이나 복잡한 렌더링 컨텍스트가 필요 없습니다.

오늘 우리는 대화형 SVG 엔진을 처음부터 직접 코딩하는 방법에 대해 이야기할 것입니다. 당황하지 마십시오. 논리는 사실 믿을 수 없을 정도로 간단합니다.

---

## 오해 깨기: SVG는 이미지가 아닙니다

우리는 SVG를 이미지로 사용하는 데 너무 익숙해져 있습니다: `<img src="logo.svg" />`. 이렇게 하면 SVG는 죽은 것입니다. 브라우저는 그것을 닫힌 픽셀 블록으로 취급하며, 내부의 어떤 것에도 접근할 수 없고 특정 경로에 클릭 이벤트를 바인딩하는 것은 꿈도 꿀 수 없습니다.

SVG에 생명을 불어넣으려면 첫 번째 규칙은 <strong>반드시 HTML에 인라인(inline)해야 한다는 것</strong>입니다.

```html
<div id="editor">
  <svg viewBox="0 0 800 600">
    <circle cx="100" cy="100" r="50" fill="red" />
    <path d="M..." fill="blue" />
  </svg>
</div>
```

코드를 DOM 트리에 직접 포함시키면 마법이 일어납니다. 그 `<circle>`과 `<path>`는 표준 `<div>` 또는 `<button>` 태그와 다를 바 없습니다. `document.querySelector('circle')`을 사용하여 캡처하고, `addEventListener`로 리스너를 바인딩하고, 심지어 CSS로 마우스를 올릴(hover) 수도 있습니다.

이것이 모든 상호작용의 유일한 기반입니다.

## 식별 시스템 구축: 요소에 "ID 카드" 발급하기

디자이너가 Figma에서 내보낸, 수백 개의 경로가 얽혀 있는 믿을 수 없을 정도로 복잡한 SVG를 받았다고 가정해 봅시다. 이러한 요소에는 아마도 `id`가 없을 것이고, 있다 하더라도 `Rectangle_12_copy`와 같이 짜증 나는 이름일 것입니다.

우리가 편집기를 구축하고 있다면, 코드에서 사용자가 어떤 요소를 클릭했는지 어떻게 알 수 있을까요?

렌더링을 위해 컨테이너에 SVG를 던지기 전에, 진정한 시각적 태그(`path`, `rect`, `circle`, `ellipse`, `polygon`, `line` 등)를 모두 반복하고 `data-editor-id`와 같은 고유한 식별자로 태그를 지정하는 간단한 스크립트를 작성해야 합니다.

![data-editor-id로 SVG 요소에 자동으로 태그 지정 데모](/content/images/interaction-code.png)

> <strong>함정 경고:</strong> `<defs>`, `<clipPath>` 또는 `<mask>` 안의 요소는 절대 건드리지 마십시오. 이들은 SVG의 렌더링 정의 레이어이지 사용자가 캔버스에서 드래그할 수 있는 물리적 엔터티가 아닙니다. 또한 `<g>`(그룹) 태그는 주의해서 처리해야 합니다. 많은 복잡한 변환(`transform`)이 그룹에 연결되어 있으며, 드래그할 때 우리는 종종 전체 그룹을 함께 드래그하기 때문입니다.

## 클릭 선택: 성가신 버블링과 보이지 않는 영역

SVG 요소는 DOM 노드이기 때문에 클릭 이벤트를 바인딩하는 것은 물을 마시는 것만큼 간단해 보입니다:

```javascript
element.addEventListener('pointerdown', (e) => {
  console.log('선택되었습니다!', e.target);
});
```

하지만 실제로 시도해 보면 즉시 두 가지 함정에 빠지게 됩니다.

<strong>첫 번째 함정은 이벤트 버블링(event bubbling)입니다.</strong> 
경로를 클릭하면 이벤트가 먼저 이 `<path>`에서 발생하고 상위 `<g>`로 버블링된 다음 마지막으로 가장 바깥쪽 `<svg>`에 도달합니다. 일반적으로 우리는 "선택 취소"(빈 공간을 클릭하면 선택 취소)를 위해 `<svg>`에 클릭 이벤트를 바인딩합니다. 버블링을 멈추지 않으면(`e.stopPropagation()`), 사용자가 요소를 클릭하는 순간 이벤트가 최상위 계층으로 버블링되어 즉시 선택 취소를 트리거합니다. 화면을 쳐다보며 클릭이 허공으로 사라진 것 같은 느낌을 받게 됩니다.

<strong>두 번째 함정은 "가는 선은 클릭할 수 없다"는 것입니다.</strong> 
`stroke-width="1"`인 매우 가는 선이 있는 경우, 사용자는 그것을 클릭하기 위해 저격수 수준의 마우스 정밀도를 가져야 합니다. SVG에는 놀랍도록 우아한 해결책이 있습니다. 마우스 이벤트를 포착하기 위해 특별히 설계된, 완전히 투명하지만(`stroke="transparent"`) 매우 두꺼운(예: `stroke-width="20"`) "고스트 경로(ghost path)"를 겹쳐 놓는 것입니다.

## 드래그의 핵심 법칙: 좌표가 왕이다

드래그 논리는 누구나 외우고 있습니다. `pointerdown`은 시작점을 기록하고, `pointermove`는 차이(delta)를 계산하며, `pointerup`은 동작을 종료합니다.

하지만 SVG에서 화면에서 움직이는 마우스의 픽셀 차이(Screen Coordinate)를 직접 가져와 SVG 요소의 `x` 및 `y` 속성에 강제로 적용하면, 요소가 즉시 <strong>태양계 밖으로 날아가는 것</strong>을 발견하게 될 것입니다.

왜 그럴까요? 화면 좌표계와 내부 SVG 좌표계는 서로 다른 짐승이기 때문입니다. SVG에는 고유한 `viewBox`가 있고, 웹 페이지가 확대되어 있을 수 있으며, 요소 자체가 `transform: scale(0.5)`를 가진 여러 `<g>` 그룹 안에 중첩되어 있을 수도 있습니다.

<strong>유일한 정답은 `getScreenCTM()`을 사용하는 것입니다.</strong> 

이것은 SVG가 제공하는 기본 메서드로, Current Transform Matrix의 약자입니다. 요소와 상위 요소 간의 좌표 변환 행렬을 검색하여, 마우스의 "화면 움직임"을 "내부 SVG 좌표 움직임"에 완벽하게 매핑할 수 있습니다.

```javascript
// 현재 요소의 변환 행렬 가져오기
const ctm = element.getScreenCTM();
// 화면 차이를 실제 SVG 좌표 차이로 변환
const svgDx = screenDx / ctm.a;
const svgDy = screenDy / ctm.d;
```

이것이 우리가 [SVG do.](/ko)를 위해 구축한 드래그 엔진의 핵심 논리입니다. 행렬 계산이 정확하기만 하면, 캔버스가 아무리 깊게 중첩되거나 확대되어 있어도 요소는 마우스 커서에 완벽하게 달라붙어 따라다닙니다.

## 강조 상태의 우아한 구현

사용자가 요소를 선택했을 때 시각적 피드백을 제공해야 하지 않을까요?

![SVG 선택 및 강조 메커니즘 데모](/content/images/clean-highlight-demo.png)

가장 무식한 접근 방식은 `stroke`(선)을 직접 밝은 파란색으로 변경하는 것입니다. 하지만 이렇게 하면 디자이너의 원래 색상이 파괴되며, 나중에 복원하기 위해 원래 색상을 힘들게 기억해야 합니다.

<strong>훨씬 더 우아한 접근 방식은: 경계 상자(Bounding Box) 그리기입니다.</strong>

SVG는 믿을 수 없을 정도로 강력한 API인 `getBoundingClientRect()`를 제공합니다. 요소를 선택하면, 원래 요소 위에 겹쳐서 채우기가 없고 밝은 파란색 선이 있는 `<rect>` 요소를 동적으로 생성합니다. 이 경계 상자의 네 모서리에 4개의 작은 점을 그려 전형적인 크기 조정 핸들(resize handles)을 만들 수도 있습니다.

## 결론

보이십니까? 이 모든 상호작용은 가장 기본적인 DOM API와 수학적 행렬을 벗어나지 않았습니다. 무거운 타사 라이브러리를 버리고 SVG의 기본 논리를 깊이 이해하면, 브라우저 내에서 미니 Figma를 혼자서 직접 코딩할 수도 있습니다. 한번 해보십시오. 기본 웹 기술의 힘에 절대적으로 경탄하게 될 것입니다.
