# SVG + JSインタラクション：クリック、ドラッグ、ハイライト可能なベクターグラフィックス

サーバールームのトポロジーマップ、劇場の座席予約システム、シンプルなオンラインポスターエディタなど、「インタラクティブなグラフィックス」を作成する要件を受け取ったとき、あなたの最初の反応は何ですか？

多くの人の最初の直感は、「Canvasを使おう」、あるいは単純に大規模なサードパーティのグラフィックスライブラリ（Fabric.js、Konvaなど）を導入することです。

しかし実際には、<strong>要素のクリック、ドラッグ、ハイライト</strong>を実装するだけであれば、ネイティブSVGと純粋なJavaScriptの組み合わせは驚くほど鋭く効率的な武器になります。SVGは基本的にDOMそのものであるため、重い依存関係や複雑なレンダリングコンテキストは不要です。

今日はお話しするのは、ゼロからインタラクティブなSVGエンジンを手作業でコーディングする方法についてです。慌てないでください。ロジックは実は信じられないほど簡単です。

---

## 誤解を解く：SVGは画像ではない

私たちはSVGを画像として使うことに慣れすぎています：`<img src="logo.svg" />`。もしこのように使えば、SVGは死んでしまいます。ブラウザはそれを閉じたピクセルブロックとして扱い、中の何にもアクセスできず、特定のパスにクリックイベントをバインドすることなど到底不可能です。

SVGを生き返らせるための最初のルールは：<strong>HTMLにインライン化しなければならない</strong>ということです。

```html
<div id="editor">
  <svg viewBox="0 0 800 600">
    <circle cx="100" cy="100" r="50" fill="red" />
    <path d="M..." fill="blue" />
  </svg>
</div>
```

コードをDOMツリーに直接埋め込むと、魔法が起こります。その`<circle>`や`<path>`は、標準の`<div>`や`<button>`タグと何ら変わりません。`document.querySelector('circle')`を使ってそれらを取得し、`addEventListener`でリスナーをバインドし、CSSでホバー（hover）することすらできます。

これがすべてのインタラクティビティの唯一の基盤です。

## アイデンティティシステムの確立：要素に「IDカード」を発行する

デザイナーがFigmaからエクスポートした、何百ものパスが絡み合う非常に複雑なSVGを受け取ったとしましょう。これらの要素にはおそらく`id`がなく、あったとしても`Rectangle_12_copy`のようなイライラする名前でしょう。

エディタを構築している場合、ユーザーがどの要素をクリックしたかをコードはどうやって知るのでしょうか？

SVGをレンダリングコンテナに放り込む前に、本当に視覚的なタグ（`path`、`rect`、`circle`、`ellipse`、`polygon`、`line`など）のすべてをループして、`data-editor-id`のような一意の識別子をタグ付けする簡単なスクリプトを書く必要があります。

![data-editor-idを用いたSVG要素の自動タグ付けのデモ](/content/images/interaction-code.png)

> <strong>落とし穴の警告：</strong> `<defs>`、`<clipPath>`、または`<mask>`内の要素には絶対に触れないでください。これらはSVGのレンダリング定義レイヤーであり、ユーザーがキャンバス上でドラッグするための物理的なエンティティではありません。さらに、`<g>`（グループ）タグは慎重に扱う必要があります。多くの複雑な変換（`transform`）はグループにアタッチされており、ドラッグするときはグループ全体を一緒にドラッグすることが多いためです。

## クリック選択：厄介なバブリングと見えない領域

SVG要素はDOMノードであるため、クリックイベントをバインドするのは水を飲むのと同じくらい簡単に見えます：

```javascript
element.addEventListener('pointerdown', (e) => {
  console.log('選択されました！', e.target);
});
```

しかし実際には、すぐに2つの罠に陥ります。

<strong>1つ目の罠はイベントバブリングです。</strong> 
パスをクリックすると、イベントはこの`<path>`で最初に発火し、次に親の`<g>`にバブリングし、最終的に最も外側の`<svg>`に到達します。通常、私たちは「選択解除」のために`<svg>`にクリックイベントをバインドします（空白スペースをクリックすると選択が解除されます）。バブリングを停止しない場合（`e.stopPropagation()`）、ユーザーが要素をクリックした瞬間にイベントが最上層にバブリングし、即座に選択解除がトリガーされます。あなたは画面を見つめながら、自分のクリックが空中に消えてしまったように感じるでしょう。

<strong>2つ目の罠は「細い線はクリック不可能」という問題です。</strong> 
`stroke-width="1"`の極端に細い線がある場合、ユーザーはそれをクリックするためにスナイパーレベルのマウス精度を必要とします。SVGには信じられないほどエレガントな解決策があります：マウスイベントをキャッチするためだけに特別に設計された、完全に透明（`stroke="transparent"`）だが非常に太い（例：`stroke-width="20"`）「ゴーストパス」を重ねるのです。

## ドラッグの核心法則：座標が王様

ドラッグのロジックは誰もが暗記しています：`pointerdown`で開始点を記録し、`pointermove`で差分（delta）を計算し、`pointerup`でアクションを終了します。

しかしSVGでは、画面上で動くマウスのピクセル差分（Screen Coordinate）をそのままSVG要素の`x`と`y`属性に強制的に適用すると、要素が瞬時に<strong>太陽系の外に飛んでいく</strong>ことに気づくでしょう。

なぜか？画面の座標系と内部のSVG座標系は2つの異なる獣だからです。SVGには独自の`viewBox`があり、Webページがズームインされている可能性があり、要素自体が`transform: scale(0.5)`を持ついくつかの`<g>`グループの中にネストされている可能性すらあります。

<strong>唯一の正解は`getScreenCTM()`を使うことです。</strong> 

これはSVGが提供するネイティブメソッドで、Current Transform Matrixの略です。要素とその親の間の座標変換行列を取得することで、マウスの「画面の動き」を「内部のSVG座標の動き」に完璧にマッピングできます。

```javascript
// 現在の要素の変換行列を取得
const ctm = element.getScreenCTM();
// 画面の差分を実際のSVG座標の差分に変換
const svgDx = screenDx / ctm.a;
const svgDy = screenDy / ctm.d;
```

これが私たちが[SVG do.](/ja)のために構築したドラッグエンジンの核心ロジックです。行列計算が正しい限り、キャンバスがどれだけ深くネストされていたりズームされていたりしても、要素はあなたのマウスカーソルに完璧に追従します。

## ハイライト状態のエレガントな実装

ユーザーが要素を選択したとき、何らかの視覚的フィードバックを与える必要がありますよね？

![SVGの選択とハイライトメカニズムのデモンストレーション](/content/images/clean-highlight-demo.png)

最も強引なアプローチは、その`stroke`（線）を直接明るい青に変更することです。しかし、これではデザイナーの元の色が破壊されてしまい、後で復元するために元の色を苦労して覚えておかなければなりません。

<strong>はるかにエレガントなアプローチは：バウンディングボックス（Bounding Box）を描画することです。</strong>

SVGは信じられないほど強力なAPIを提供しています：`getBoundingClientRect()`。要素を選択したら、元の要素の上に重ねて、塗りつぶしがなく明るい青の線を持つ`<rect>`要素を動的に生成します。このバウンディングボックスの四隅に4つの小さな点を描画して、古典的なリサイズハンドルを作成することさえできます。

## 結論

お分かりいただけましたか？これらのインタラクションはすべて、最も基礎的なDOM APIと数学的な行列から離れることはありませんでした。重いサードパーティライブラリを捨て、SVGの基礎となるロジックを深く理解すれば、ブラウザ内でミニFigmaを一人で手作りすることだって可能です。ぜひ試してみてください；あなたはネイティブWebテクノロジーの力に絶対に驚嘆するはずです。
