## 矢量 vs 位图：这场争论早该结束了

"该用 SVG 还是 PNG？" — 这是每个设计师和前端开发者都会遇到的问题。

答案不是非黑即白。两种格式各有最适合的场景。这篇文章会从实际使用角度帮你做选择。

---

## 一张表看懂核心区别

| 维度 | SVG | PNG |
|------|-----|-----|
| 图像类型 | 矢量（数学公式） | 位图（像素网格） |
| 缩放 | 无限无损 | 放大会模糊 |
| 文件大小 | 简单图形极小 | 跟分辨率成正比 |
| 透明度 | 原生支持 | 原生支持 |
| 颜色深度 | 无限制 | 每通道 8/16 bit |
| 动画 | CSS/JS/SMIL | 只能 APNG |
| 浏览器兼容 | 所有现代浏览器 | 所有浏览器 |
| SEO | 文本可索引 | 需要 alt 文本 |
| 适用场景 | 图标、Logo、UI、图表 | 照片、截图、复杂渐变 |

---

## 什么时候用 SVG？

### ✅ 图标和 UI 元素

这是 SVG 的"主场"。无论 24×24 的小图标还是网站 Logo，SVG 都能保证在任何屏幕上都锐利清晰。

### ✅ 数据可视化图表

ECharts、D3.js 等图表库底层都是 SVG。图表需要在小尺寸下保持文字清晰，SVG 是最佳选择。

### ✅ 响应式设计

一个 SVG 文件适配所有分辨率。不需要为手机、平板、桌面分别准备不同尺寸的图。

### ✅ 需要交互的场景

图标悬停变色？点击展开的动效？SVG 配合 CSS 可以轻松实现。

---

## 什么时候用 PNG？

### ✅ 照片和实景图像

照片是连续的色彩渐变，SVG 无法还原。照片类内容用 WebP 或 JPEG 更好。

### ✅ 复杂渐变和阴影

极其复杂的光影效果用 SVG 实现会让代码变得巨大而复杂。这时用位图更实际。

### ✅ 老浏览器兼容

如果你必须支持 IE11 或更老的浏览器，PNG 是更安全的选择（尽管现在这种情况越来越少了）。

### ✅ 固定尺寸的界面元素

如果一个图标的尺寸永远不会改变，且已经有了对应分辨率的 PNG，直接用它就好。

---

## 混合使用策略

实际上，现代网页往往是 SVG + 位图混合的：

- **Logo 和图标**：SVG（保证清晰）
- **产品图、Banner**：WebP 或 JPEG（体积小）
- **UI 装饰元素**：SVG（可交互、可动效）
- **用户上传的内容**：保持原格式

---

## 快速决策流程图

```
需要缩放吗？ → 是 → SVG
需要交互/动画？ → 是 → SVG
是照片吗？ → 是 → PNG/WebP/JPEG
有复杂渐变吗？ → 是 → PNG/WebP
文件很小但要求清晰？ → SVG
```

用我们的 SVG 编辑器，你可以随时在 SVG 和 PNG 之间转换——上传一个 SVG，导出为任意分辨率的 PNG，或反过来处理。
